# LC lossy compression with a lossless residual

`lc_lossy_residual.cpp` links three standalone CPU entry points generated by
the [LC Framework](https://github.com/burtscher/LC-framework):

1. a lossy compressor,
2. its matching decompressor, and
3. a lossless compressor for the floating-point residuals.

The input must be a headerless array of IEEE-754 `float` (`f32`) or `double`
(`f64`) values. The selected type must match the quantizer baked into the
generated LC codec.

## Build (float32 example, absolute error bound 0.01)

Run these commands from the root of an LC Framework checkout. Copy
`lc_lossy_residual.cpp` into that directory first.

```sh
./generate_standalone_CPU_compressor_decompressor.py \
  "QUANT_ABS_0_f32(0.01)" "TUPL4_1 RRE_1 CLOG_1"
mv compressor-standalone.cpp compressor-lossy.cpp
mv decompressor-standalone.cpp decompressor-lossy.cpp

./generate_standalone_CPU_compressor_decompressor.py \
  "" "DIFF_4 RLE_1 CLOG_1"
mv compressor-standalone.cpp compressor-lossless.cpp

g++ -O3 -march=native -fopenmp -mno-fma -ffp-contract=off \
  -I. -std=c++17 -Dmain=lc_lossy_compress_main \
  -c compressor-lossy.cpp -o compressor-lossy.o
g++ -O3 -march=native -fopenmp -mno-fma -ffp-contract=off \
  -I. -std=c++17 -Dmain=lc_lossy_decompress_main \
  -c decompressor-lossy.cpp -o decompressor-lossy.o
g++ -O3 -march=native -fopenmp -mno-fma -ffp-contract=off \
  -I. -std=c++17 -Dmain=lc_lossless_compress_main \
  -c compressor-lossless.cpp -o compressor-lossless.o
g++ -O3 -march=native -fopenmp -mno-fma -ffp-contract=off \
  -std=c++17 lc_lossy_residual.cpp compressor-lossy.o \
  decompressor-lossy.o compressor-lossless.o -o lc_lossy_residual
```

For `float64`, generate `QUANT_ABS_0_f64(...)`, use word-size-8 components
where applicable, and run the result with `f64`. LC's search mode should be
used to choose better component pipelines for a particular dataset; the
pipelines above are concrete defaults, not universally optimal choices.

## Run

```sh
./lc_lossy_residual input-f32.raw results/run1 f32
```

This creates:

- `results/run1.lossy.lc` — the LC lossy stream
- `results/run1.approx.raw` — the decompressed approximation
- `results/run1.residual.lc` — `original - approximation`, compressed by LC
  without a lossy preprocessor

The uncompressed temporary residual is removed after successful compression.
The program also prints the maximum absolute error, RMSE, and stored sizes.

The residual is stored losslessly, meaning decompression reproduces the
computed residual values bit-for-bit. Floating-point addition of the residual
to the approximation is not guaranteed to reconstruct every original bit
pattern. If exact original-file reconstruction is required, store a bytewise
XOR residual instead of a floating-point subtraction.

## Separate Python benchmark runners

Run the lossless comparisons for each f32 input, appending to the same CSV:

```sh
python3 lc_lossless_compress.py input-f32.raw --lc-dir /path/to/LC-framework
```

The default codecs are LC, SZ3, ZFP, PFPL, Bzip2, Zstandard, SLEEK, SPspeed,
SPratio, and resident ZIP/Deflate via zip/unzip. Select a subset with
`--tools lc bzip2 zstandard sleek spspeed spratio zip`. CPU SLEEK and FPcompress
commands default to the executables in `~/bin`; each executable has an override
flag shown by `--help`. SPspeed is FPcompress's speed-oriented codec. ZIP uses
the resident zip/unzip, not the PKWARE PKZIP product.

Measurements append to `testrpts/lossless_results.csv` beside the script across
all invocations; override with `--csv /path/to/common.csv`. Existing rows are
preserved, and a file lock protects concurrent appends. A mismatched existing
header is rejected. Each row has exactly these columns in order:

1. `file` (input basename)
2. `command`
3. `command_args`
4. `original_bytes`
5. `compressed_bytes` (complete output, including archive headers)
6. `compression_ratio` (original/compressed)
7. `exact_reconstruction` (byte-for-byte comparison)
8. `compression_time_seconds`
9. `compression_throughput_MB_s`
10. `decompression_time_seconds`
11. `decompression_throughput_MB_s`

Times use a monotonic wall clock and include process startup and file I/O.
Throughput uses original bytes / time / 1,000,000 for both directions. LC
pipeline search, code generation, compilation, and reconstruction verification
are excluded from codec timings. Each combination runs once, so very short
inputs are sensitive to startup overhead. The LC pipeline is recorded within
`command_args`. No per-run statistics JSON or command log is retained;
temporary codecs, compressed streams, and reconstructions are cleaned up.

Defaults test Bzip2 levels 1/5/9, Zstandard levels 1/3/9/19/22, and ZIP levels
1/6/9. Override with `--bzip2-levels`, `--zstd-levels`, and `--zip-levels`.
A failed byte-for-byte reconstruction is recorded as false and stops the run.
Missing executables are reported before benchmarking, rather than silently
skipping a requested codec.

Run only the LC lossy-data + lossless XOR-residual epsilon sweep:

```sh
python3 lc_two_part_compress.py input-f32.raw --lc-dir /path/to/LC-framework
```

The sweep runner preserves the ten logarithmic bounds from 0.01 through 10,
quality statistics, generated codecs, and exact XOR reconstruction checks. It
writes one CSV row per epsilon plus JSON reports and a command log under
`testrpts/INPUT_LDLLR_TIMESTAMP/`. It requires only LC and a C++ compiler,
and supports f32 or f64 preprocessors. Both runners accept `--compiler` and `--lossless-pattern`; the sweep also accepts
`--output-dir`, `--performance`,
`--lossy-preprocessor` and `--lossy-pattern`.

Keep the two scripts together because the lossless runner imports shared LC
helpers from the sweep runner. Run them sequentially when sharing an LC
checkout, since its generator writes fixed standalone source filenames.

The lossy-data + lossless-residual runner also appends one combined result per
epsilon to the same `testrpts/lossless_results.csv`. Override that destination
with `--lossless-csv`. These rows record total bytes from both streams, the
final compression factor, and verified exact reconstruction. Epsilon,
preprocessor, and both pipelines are recorded in `command_args`. Timing and
throughput cells are blank because this runner does not measure the complete
two-part codec time. Its detailed sweep CSV remains unchanged. The separate
lossy-residual experiment does not append to the lossless comparison CSV.

## Run all 18 benchmark inputs

`./runtests` runs `lc_lossless_compress.py` followed by
`lc_two_part_compress.py` for each of the 18 f32 files, sequentially.
Both append to the same shared CSV. Detailed sweep outputs are saved under
this project's `testrpts` folder. The batch stops on the first failed command.

Use `./runtests --dry-run` to preview all 36 commands, `--csv` to change
the shared CSV, or `--lc-dir` to choose another LC checkout. Optional positional
file paths run a selected subset instead of the full list. This batch runs the
lossy-data/lossless-residual experiment; the separate LDLR runner is available
independently.

The three `FPDouble_Datasets/*.sp.f32` originals are SPDP-compressed, as
documented by https://userweb.cs.txstate.edu/~burtscher/research/datasets/FPsingle/.
The batch uses their decompressed `.raw.f32` counterparts. The originals are
preserved. Decompressed sizes were checked against the SPDP block headers,
and all three raw outputs passed SPDP recompression/decompression round trips.
runtests checks input sizes before launching benchmarks.
